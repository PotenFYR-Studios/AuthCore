# 📦 Building & keeping AuthCore in sync for 26.x

Minecraft changed the rules at **26.1**: Mojang released the game **unobfuscated** (readable
Mojang names in the shipped jar, parameter names included) and **Fabric's intermediary no
longer exists** for that era. The Fabric project [announced](https://fabricmc.net/2025/10/31/obfuscation.html)
that yarn is discontinued and mods must migrate to Mojang names.

That is why AuthCore ships **two jars**:

| Jar | Source tree | Names | Minecraft | Java level |
|:----|:------------|:------|:----------|:-----------|
| `authcore-<v>.jar` | `src/main/java` + `src/client/java` | Yarn | 1.16.0 – 1.21.11 | 16 |
| `authcore-<v>-26x.jar` | `src/mojang26x/java` | Mojang | 26.1+ | 25 |

The two name-spaces **cannot coexist in one compiled jar** — the game at runtime uses either
intermediary (≤1.21.11) or Mojang names (≥26.1). Installing the right jar per server version
is expected behaviour for every mod today.

## Building

```bash
# Classic universal jar (1.16 - 1.21.11), Java 21 JDK needed
./gradlew clean build                     # -> build/libs/authcore-1.0.0.jar

# 26.x jar (26.1+), Java 25 JDK needed (self-contained Gradle project)
cd 26x && ./gradlew clean build           # -> 26x/build/libs/authcore-1.0.0.jar
```

The `26x/` project uses **loom 1.16.x**, **no mappings** (the game is unobfuscated),
`fabric.loom.disableObfuscation=true` and Java 25. CI builds and verifies both jars on every
push (`.github/workflows/ci.yml`).

## Keeping the two sources in sync

`src/mojang26x/java` is the yarn source **migrated to Mojang names** (loom's
`migrateMappings` task, see [Fabric docs](https://docs.fabricmc.net/develop/porting/mappings/loom)).
When you change business logic, port the change to both trees (mechanical renames stay
identical; 26.x-only API differences are small).

### Migrating a change (or re-syncing) with loom

```bash
# 1. From a clean copy of the repo with loom 1.16.x and yarn 1.21.11 configured:
./gradlew migrateMappings \
  --mappings "net.minecraft:mappings:1.21.11" \
  --overrideInputsIHaveABackup
#    (default input: src/main/java - migrate server code)
# 2. Then the 26.2-specific manual fixes (mixin targets, renamed APIs)
#    as documented below; commit the result to src/mojang26x/java.
```

> ⚠️ Back up first: `--overrideInputsIHaveABackup` rewrites in place.

### 26.x API differences already handled in `src/mojang26x`

- `net.minecraft.block.*` imports → `net.minecraft.world.level.block.*` (wildcard imports are
  NOT rewritten by migrateMappings)
- `displayClientMessage(Component, boolean)` → `sendSystemMessage(Component, boolean)`
- `ClickType` → `ContainerInput` (same constants)
- `MinecraftClient` → `Minecraft`; `ClientPlayNetworkHandler` → `ClientPacketListener`
- Screen model: `render(GuiGraphics)` → `extractRenderState(GuiGraphicsExtractor)` +
  `extractBackground(...)`; `setScreen` → `setScreenAndShow`; `drawCenteredString` →
  `graphics.centeredText(...)`
- Reflection string class names updated to Mojang paths (e.g.
  `net.minecraft.client.multiplayer.TransferState`)

### How to find 26.2 API ground truth

The 26.2 game jar is unobfuscated, so `javap` gives exact answers:

```bash
javap -cp ~/.gradle/caches/fabric-loom/26.2/minecraft-merged.jar \
  net.minecraft.client.gui.screens.Screen
```
